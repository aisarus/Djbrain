# Codex Mission — Speech Twin v2: Real Behavioral Simulator

## Why this mission exists

The current draft PR #2 is a useful API sketch, but it is not a meaningful person-specific speech simulator.

Do not discard the branch. Continue on `codex/speech-twin-v1`, but treat the current implementation as scaffolding only.

The target is not to create files with the right names. The target is to demonstrate that the same incoming message produces materially different, explainable and person-consistent speech behavior depending on relationship, recent dialogue, active state, memory and identity evidence.

## Non-negotiable completion rule

Do not report completion while any of the following is true:

- `npm test` has any failing test, including legacy tests;
- `npm run build` fails;
- the benchmark is generated by cloning a few messages across labels;
- modules are only hardcoded topic-to-label maps;
- the output can be explained by a fixed prefix table;
- relationship, identity and memory inputs do not change observable behavior;
- the personalized system does not outperform a generic baseline on frozen evaluation;
- persistence and restart behavior are not tested;
- private or restricted memory can enter generation without explicit scope;
- the pull request still describes failing tests as an acceptable blocker.

Missing local dependencies are not an external blocker. Install dependencies and repair the repository. Pre-existing failures are part of this mission.

## Phase 0 — Repository stabilization

Before expanding Speech Twin:

1. Install dependencies.
2. Fix all currently failing legacy tests without weakening or deleting them.
3. Make `npm test` pass with zero failures.
4. Make `npm run build` pass.
5. Ensure CI runs both commands.
6. Add a regression test for every legacy bug fixed.

Do not continue to the final completion report until these gates are green.

## Phase 1 — Replace the mock interpretation layer

### Conversation Situation Interpreter

Replace the current single regex classifier with a structured interpreter that uses:

- the current message;
- at least the last 3 dialogue turns when available;
- participant IDs;
- relationship record;
- current working-memory goal/topic;
- active temporal state;
- ambiguity signals;
- contradiction with recent context.

The interpreter must support multiple simultaneous signals. A message may be both a correction and playful provocation, or both a factual question and a request for reassurance.

Output must include ranked hypotheses, not only one topic label:

```text
primarySituation
alternativeSituations[]
confidence
supportingEvidence[]
counterEvidence[]
missingContext[]
```

Required tests:

- same text with different preceding turns produces different situation hypotheses;
- quotation and irony reduce confidence;
- a correction after a misunderstanding differs from an isolated negative sentence;
- a close relationship and a public audience produce different social-stakes estimates;
- mixed-language messages are not reduced to `small_talk`.

### Internal State Hypothesis

The internal-state model must not be a direct topic lookup table.

It must combine:

- situation hypotheses;
- relationship trust/closeness;
- active temporal or conversational state;
- identity patterns with evidence and exceptions;
- recent feedback;
- uncertainty caused by missing evidence.

Return at least the top 2 hypotheses when confidence is below 0.75.

Each hypothesis must contain:

- state vector;
- probability/confidence;
- evidence IDs;
- counter-evidence IDs;
- alternative explanation;
- whether the hypothesis is safe to use for generation.

No unsupported internal-state value may be persisted as a verified fact.

## Phase 2 — Behavioral profile and speech policy

Create a real `SpeechBehaviorProfile` abstraction backed by evidence, not hardcoded global defaults.

Required dimensions:

- directness distribution by context;
- response-length distribution by context;
- humor modes and triggers;
- profanity probability and function by relationship/context;
- hedging and uncertainty style;
- disagreement style;
- correction style;
- emotional-support style;
- topic-ending behavior;
- question-asking tendency;
- repetition and self-correction tendency;
- punctuation and parenthetical tendencies;
- code-switching conditions;
- vocabulary/register preferences;
- anti-patterns and exceptions.

Profile entries must include:

```text
id
feature
contextConditions
relationshipConditions
value or distribution
confidence
supportingEpisodeIds
counterExampleIds
status: candidate | verified | rejected | superseded
sensitivity
```

Create at least 40 synthetic but manually authored profile entries for tests. Do not claim they are true facts about Arseniy. Mark them as synthetic fixtures.

The runtime must select only context-applicable profile entries.

Required contrast tests:

- close vs public;
- irritated vs neutral;
- known answer vs uncertain answer;
- playful vs vulnerable context;
- same person but different historical period/state;
- explicit request for brevity vs normal response;
- relationship boundary forbidding a topic.

## Phase 3 — Real memory and identity activation

The Speech Twin path must actively use existing:

- episodic memory;
- semantic memory;
- temporal state;
- relationship registry;
- Identity Core;
- procedural/behavioral memory;
- privacy filtering;
- hybrid retrieval.

Do not merely pass these stores through constructors.

For every simulation, produce a structured activation report:

```text
consideredMemoryIds
selectedMemoryIds
rejectedMemoryIds with reasons
identityClaimIds
relationshipRecordIds
behaviorProfileEntryIds
memoryInfluenceMode: none | implicit | explicit
```

Required tests:

- irrelevant high-confidence memory is not selected;
- relevant current fact outranks superseded fact;
- memory may influence wording without being explicitly mentioned;
- explicit autobiographical reference requires supporting memory;
- restricted memory is blocked without scope;
- relationship memory is never selected without the relevant participant;
- restart restores semantic, temporal, relationship, identity and behavior-profile state.

## Phase 4 — Communicative intent and content planning

Replace single-label intent mapping with ranked intents and trade-offs.

The planner must represent at least:

- primary intent;
- secondary intent;
- suppressed intent;
- target interpersonal effect;
- risk of saying too much;
- risk of sounding generic;
- willingness to continue the topic;
- disclosure boundary;
- uncertainty strategy.

Content planning must produce actual propositions grounded in the message and selected memory. A claim such as `Respond to small_talk` is not acceptable.

Each planned claim must contain:

```text
text or structured proposition
support source
confidence
mentionability
reason for inclusion
reason for omission alternatives
```

Required tests:

- an unknown factual question produces no fabricated factual proposition;
- emotional disclosure produces support appropriate to relationship;
- disagreement may preserve closeness while rejecting the claim;
- correction after repeated misunderstanding is stronger than first correction;
- public context suppresses private autobiographical details;
- a topic-ending signal produces an intentionally short closing response.

## Phase 5 — Speech planning and realization

The deterministic realizer must be a meaningful baseline, not a prefix table.

Implement a compositional realizer that uses:

- content propositions;
- ordering policy;
- sentence-shape policy;
- discourse markers;
- directness;
- hedging;
- humor mode;
- profanity function;
- repetition/self-correction;
- punctuation mode;
- code switching;
- target length;
- relationship register.

At least 8 distinct realization mechanisms must be independently controllable and tested.

Examples of mechanisms:

- clause ordering;
- elliptical vs explicit subject;
- rhetorical question insertion;
- parenthetical aside;
- uncertainty marker placement;
- correction restart;
- intensifier selection;
- closing omission;
- repetition for emphasis;
- code-switch token insertion.

Do not hardcode a small set of complete response templates.

The same content plan with two different speech profiles must produce measurably different utterance features.

## Phase 6 — Provider mode

Keep deterministic mode for reproducible tests, but implement a provider-neutral generation adapter that receives:

- conversation situation;
- selected memory summaries;
- identity and behavior-profile entries;
- internal-state hypotheses;
- communicative intent;
- content plan;
- speech plan;
- explicit prohibited behaviors.

The provider output must be parsed into a typed result and passed through the same critic.

Use a fake provider in tests. No paid API is required.

## Phase 7 — Speech behavior critic and repair

Expand the critic to evaluate:

- factual grounding;
- temporal correctness;
- relationship fit;
- privacy scope;
- intent alignment;
- content-plan coverage;
- generic-assistant leakage;
- task-agent leakage;
- unsupported autobiographical claims;
- excessive or missing uncertainty;
- profanity function mismatch;
- caricature;
- over-polished generic prose;
- length mismatch;
- missing emotional acknowledgement;
- repetitive canned openings;
- identity-profile contradiction.

The critic must return structured, targeted repair instructions.

Repair must change the detected feature and be re-evaluated. Add tests proving at least 6 different repair classes work.

## Phase 8 — Honest frozen benchmark

Replace the generated 60-case fixture entirely.

Create at least 120 manually authored frozen scenarios. They must be explicit objects, not `Array.from`, cyclic category generation or duplicated messages with relabeling.

Minimum composition:

- 25 multi-turn scenarios with 3–8 previous turns;
- 20 paired contrast scenarios where only relationship/audience/state changes;
- 15 memory-required scenarios;
- 15 memory-forbidden or memory-unnecessary scenarios;
- 10 temporal-current-vs-historical scenarios;
- 10 ambiguous/ironic/quoted scenarios;
- 10 emotional-support or vulnerable-disclosure scenarios;
- 10 disagreement/correction/escalation scenarios;
- 5 mixed-language scenarios.

Every scenario must define structured expectations, including at least 5 of:

- allowed situation hypotheses;
- forbidden situation hypotheses;
- intent ranking;
- internal-state ranges;
- required memory IDs;
- forbidden memory IDs;
- relationship scope;
- disclosure mode;
- speech-feature ranges;
- prohibited phrases;
- required semantic content;
- temporal truth expectation;
- privacy expectation;
- maximum genericness score.

No scenario passes merely because the critic says `approved`.

## Phase 9 — Baseline comparison

Implement at least three benchmark runners:

1. generic deterministic baseline without identity/memory;
2. Speech Twin without relationship/internal-state layers;
3. complete Speech Twin.

Report per-category and overall deltas for:

- situation accuracy;
- intent accuracy;
- memory precision/recall;
- temporal correctness;
- privacy violations;
- relationship contrast accuracy;
- speech-feature fit;
- genericness;
- unsupported autobiographical claims.

The complete Speech Twin must outperform the generic baseline overall and must not regress privacy or factual grounding.

Add a machine-readable benchmark artifact under `artifacts/benchmarks/` generated by a script, not hand-written.

## Phase 10 — Human review packet

Create a command that exports blind A/B packets for manual evaluation:

```text
input conversation
candidate A
candidate B
hidden system labels
review fields
```

The packet must support comparison of:

- generic baseline vs Speech Twin;
- Speech Twin variants;
- deterministic vs provider output.

Do not include private raw evidence in exported packets.

Complete and connect persistent registry runtime for:

## Definition of Done

This mission is complete only when all conditions below are true:

- all legacy and new tests pass;
- build passes from a clean dependency installation;
- at least 120 unique, manually authored frozen scenarios exist;
- at least 25 scenarios are genuinely multi-turn;
- same-message contrast tests prove relationship/state changes behavior;
- identity, relationship, temporal and memory layers measurably affect output;
- generic baseline comparison exists and complete Speech Twin performs better;
- privacy and temporal correctness have zero critical regressions;
- persistent restart tests cover all durable registries;
- deterministic realizer is compositional rather than a fixed prefix/template table;
- critic repair is demonstrated for at least 6 failure classes;
- benchmark artifacts and blind-review export are generated by scripts;
- PR #2 contains no unresolved gate failures.

Anything less is an intermediate checkpoint, not completion.
